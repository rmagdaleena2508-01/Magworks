Sollu

A voice-first civic AI that reads government schemes, notices and laws, then explains them in plain Tamil or English — so people can find out what they're actually entitled to, in their own words.

Live site Code
Live · 101 checked data entries, each quoted from an official source

The problem

Tamil Nadu runs hundreds of welfare schemes — myScheme, the government's own catalogue, lists 234 for the state alone. The rules are public, but they're written for officers, not for the people they're meant to help: long PDFs, legal English, formal Tamil, G.O. numbers, and amounts that change quietly from one year to the next.

So the people who need help most are the least likely to find it. And when they search, the internet makes it worse — ads, old news, five different amounts for the same pension, and AI chat answers that sound sure but can't show where a single fact came from.

What I built

Sollu (சொல்லு, "say it") is voice-first: the mic is the biggest thing on the page, and every answer is read out loud by itself. A text box sits right next to it for anyone who'd rather type. You ask by voice in Tamil, English, or a mix; Sollu shows you what it heard so you can fix it; then it answers in three short lines, with the official source link and the date it was checked.

The phone never talks to an AI directly. Every request goes through a small server function that holds the keys, picks the matching checked facts, lets plain rules decide eligibility, and only then asks the model to put the answer into simple words. Speech-to-text and the spoken reply are handled by Sarvam; the understanding and plain-language explanation by Gemini.

Key engineering decisions

  • The AI never decides who gets what. "You can get it" is a high-stakes sentence, so the yes/no lives in plain TypeScript rules that anyone can read and test. The model only does the language work — understanding the question and saying the answer simply.
  • The AI can only use checked facts. The 101 entries come from official sites only (*.gov.in, *.nic.in, myScheme, CMCHIS). Every fact has a word-for-word quote, and a checker script proves each quote still exists on the saved page. The model gets only the 1–3 entries that match, never the open internet.
  • Trust, but verify the output. Before an answer is shown, the server pulls every number out of it and checks each one against the facts. Money is where a wrong answer hurts most, so this check is strict — if it fails, Sollu falls back to the plain facts. A dull right answer beats a friendly wrong one.
  • "I'm not sure" is a feature. If a question doesn't match a checked entry, Sollu says so honestly and points the person to a real office, instead of guessing.
  • Built for the free tier and slow networks. It tries the fast model first; if it hasn't answered in 4 seconds, a backup model starts alongside it (hedging) and the first good answer wins. The spoken reply is streamed, so the voice starts in about 1–2 seconds while the rest is still being made.
  • Private by default. API keys live only on the server, never on the phone. Nothing is stored — no database, model storage turned off — and the page reminds people not to say their name, Aadhaar or phone number.

A closer look

The home page — one line, two buttons: ask by voice, or check a scheme. Built to be understood in a second, on any phone.

The Ask page — the mic is the biggest control, every answer is read aloud, and each one shows its official source and the date it was checked.

Ask by voice, check what you may be eligible for in a few taps, or photograph a notice and have it explained — all grounded in checked data.
